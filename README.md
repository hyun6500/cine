# 주현 시네마테크 — 시청기록 아카이브 앱 v2.23 (모듈 구조)

15년 관람 기록을 구글 스프레드시트 DB로 보여주는 개인 아카이브.
오운완(hyun6500.github.io/JH)과 같은 GitHub Pages 정적 앱 + Apps Script 쓰기 패턴.

## 파일 구조

## 신규 칼럼 4개 반영
| 칼럼 | 앱에서의 사용 |
|---|---|
| `관람상태` | '중도포기' 16행은 파싱 단계에서 제외 — 모든 화면·집계에 안 나옴 |
| `시즌` | 카드·모달에 `S1` 태그. 작품 동일성 키에 포함 → 같은 ID라도 시즌 다르면 별도 작품 |
| `TMDB타입` | 포스터·백드롭 조회 시 movie/tv 결정. **카테고리로 추론하지 않음.** 타입 미기재+ID 보유 시 movie→tv 순 폴백 |
| `넷플릭스평가` | 포스터 우하단 👍👍/👍/👎 배지 · 둘러보기 '인생작 셀렉션' 캐러셀 · 대시보드 평가 분포 차트 · 포스터 월 평가 칩 필터 |

작품 동일성 키: `TMDB_ID + 시즌` 우선, 없으면 정규화 제목. 같은 작품인데 일부 행에만
ID가 있는 경우(재관람 지연기록 등)는 로딩 시 제목→ID 백필로 보정한 뒤 키를 만듭니다.

## 설치

### 1. 설정은 js/config.js 한 곳에서만
개인 값은 전부 `js/config.js`에 있습니다. **앞으로 코드를 업데이트할 때 이 파일만 그대로 두면
키가 지워지지 않습니다.** (core.js는 마음 놓고 덮어쓰세요.)

```js
window.CINE_CONFIG = {
  SHEET_ID: "1xf26f…",         // 입력돼 있음
  TMDB_KEY: "…",               // 방법 A: 본인 v3 키 (클라이언트 노출)
  APPS_SCRIPT_URL: "",         // 방법 B: 프록시 + 기록 추가/수정 — 아래 2번 배포 후 URL
};
```
※ 편집 비밀번호는 config.js에 두지 않습니다. Apps Script의 `TOKEN`이 곧 비밀번호이고, 앱에서 직접 입력합니다.
⚠️ URL은 **끝까지** 붙여넣고 따옴표로 닫아야 합니다. 주소창에 `…`로 줄여 보이는 걸 복사하면
문자열이 안 닫혀 앱 전체가 멈춥니다(증상: 클릭 무반응 + "불 꺼지는 중…"에서 정지).
정상 URL은 `/exec`로 끝납니다 — Apps Script [배포 → 배포 관리]의 복사 아이콘을 쓰세요.

TMDB_KEY와 APPS_SCRIPT_URL 중 하나만 있으면 포스터가 뜹니다. 둘 다 있으면 키 직접 호출 우선.
단, **기록 추가·수정 기능은 APPS_SCRIPT_URL이 있어야** 동작합니다.

### 2. Apps Script 배포 (기록 추가 + 프록시)
1. 구글 시트 → 확장 프로그램 → Apps Script → `Code.gs` 내용 붙여넣기
2. `TOKEN` 값을 원하는 **편집 비밀번호**로 변경 (앱에서 이 값을 입력합니다)
3. (프록시 쓸 경우) 프로젝트 설정 → **스크립트 속성**에 `TMDB_KEY` 추가
4. 배포 → 새 배포 → 웹 앱 / 실행: **나** / 액세스: **모든 사용자** → URL 복사
5. ⚠️ 코드를 고치면 반드시 **"새 버전으로" 재배포** — 안 하면 옛 코드가 계속 돕니다
6. 동작 확인: `{URL}?action=ping` 접속 시 `{"ok":true,...}`

### 3. GitHub Pages 배포

## 기록 추가
- **한 편 추가**: TMDB 검색 → 선택하면 감독·장르·연도·ID·타입 자동. TV 선택 시 시즌 입력칸 등장.
  검색 없이 직접 입력만으로도 저장 가능.
- **넷플릭스 CSV**: Title/Date CSV를 올리면
  - 회차 단위 행을 **시리즈명+시즌으로 묶고** 시작~종료일 산출, **종료일이 대표 날짜**, 화수는 최대 회차번호
  - 기존 기록과 대조: 시리즈는 정규화제목+시즌 일치 시 '보유', 영화는 같은 날짜면 '중복',
    다른 날짜면 '재관람'(규칙대로 복수 카운팅 — 기본 체크됨)
  - 미리보기에서 제목·시즌 수정, 체크 선택 후 전송
  - '선택 행 TMDB 매칭' 버튼: 검색 결과가 **정규화 제목 완전 일치일 때만** ID·감독·장르 채움 (오매칭 방지)
- 저장 성공 시 화면에도 즉시 반영(낙관적 갱신). 시트 값이 진실이므로 새로고침하면 시트 기준으로 다시 로드.
- 앱이 시트에 쓰는 분류값은 **TMDB제작/감독·TMDB장르 칼럼**에만 들어갑니다 (KOBIS 칼럼은 건드리지 않음).

## 기록 수정 (v2.1)
상세 모달의 각 관람 회차에 **수정** 버튼이 있습니다.
- **작품 정보**: 제목·개봉연도·감독·장르·제작국가·TMDB_ID·타입. 'TMDB에서 찾기'로 고르면 한 번에 채워집니다.
  감독·장르는 KOBIS 칼럼에 기록되므로 화면에 바로 반영됩니다.
- **관람 정보**: 날짜·시작일·시즌·카테고리·플랫폼·위치·상영시각·화수·동반메모·평점·넷플릭스평가·한줄평

  (관람 정보는 언제나 그 회차에만 적용).
- 저장은 Apps Script `update` 액션 → `no`로 행을 찾아 해당 칼럼만 덮어씁니다. 화이트리스트 밖 필드는 무시됩니다.

## 아키텍처 결정 (질문 답)
1. **메타데이터는 시트 저장분 사용** — 맞습니다. 감독·장르·연도·등급은 매 방문 API 호출 없이 시트 값만 씀.
2. **포스터**: TMDB 실시간 조회 + localStorage 캐시(`pc2`) 유지. poster_path를 시트에 넣는 방법도 가능하지만
   칼럼 1개·991행 채우기 관리 비용 대비, 캐시가 이미 재방문을 0콜로 만들어 이득이 작음.
   TMDB_ID 329건은 정확 조회되고, ID 없는 작품만 멀티 검색 폴백.
3. **키 노출**: GitHub Pages 정적 사이트에선 클라이언트에 넣는 값은 어떤 방식이든 결국 공개됩니다
   (`.gitignore`로 빼면 배포에 포함되지 않아 동작 자체가 안 함).
   - TMDB v3 키는 읽기 전용·무료라 실위험은 '남이 내 쿼터를 씀' 수준 → 노출 감수 가능
   - 정말 감추려면 **Apps Script 프록시**(방법 B): 키는 스크립트 속성에만 있고 클라이언트엔 프록시 URL만 노출
   - 쓰기 토큰(APP_TOKEN)도 노출되지만, 최악의 경우 스팸 행 추가 정도이고 시트 버전 기록으로 복구 가능.
     신경 쓰이면 주기적으로 토큰만 교체(Code.gs와 CONFIG 동시 변경)

## v2.23 변경 요약 — 뒤로가기 · 달력 분할 보강 · 하루 순서 바꾸기

### ① 뒤로가기가 앱 안에서 동작 (`js/nav.js` 신설 — 17번째 파일)
탭을 옮기고 팝업을 열어도 히스토리에 아무것도 안 쌓여서, 뒤로가기 한 번에 앱을 벗어났습니다.
이제 **탭 전환과 팝업이 각각 히스토리 한 칸**이 됩니다.
- 탭 전환 → `{ cine:"tab", tab:"wall" }`
- 팝업 열기 → `{ cine:"layer", name:"modal", depth:N }`

**핵심은 닫기 경로를 하나로 모은 것**입니다. ✕ 버튼·배경 탭·ESC로 닫을 때도 DOM을 직접
건드리지 않고 `history.back()`만 부르고, 실제 닫기는 `popstate`가 합니다. 직접 닫으면
히스토리에 유령 칸이 남아 뒤로가기가 한 번 먹통이 됩니다.
등록된 팝업: 상세 모달 · 수정창 · 검색 · 스토리 · 작품 선택기 · 비밀번호 창
(비밀번호 창은 뒤로가기로 닫으면 '취소'로 처리해 대기 중인 작업이 멈추지 않게 했습니다)

### ② 달력 하루 분할 — 포스터가 없어도 조각이 보이게
분할 자체는 v2.21에 들어갔지만, 조각이 `<img>` 하나뿐이라 **포스터를 못 받으면 검은 블록**이
돼서 "한 편만 나온다"처럼 보였습니다. 이제 조각마다 타일(`.sh`)을 두고 제목 글자를 깔아둔 뒤
포스터가 도착하면 그 위를 덮습니다.

### ③ 하루에 여러 편일 때 순서 바꾸기
그 날 목록에서 **행을 길게 눌러(400ms) 끌면** 순서가 바뀌고, 달력 칸의 분할 배치도 같이 바뀝니다.
- 짧게 누르면 스크롤·클릭, 400ms 이상이면 끌기로 전환(누르자마자 잡으면 목록 스크롤이 안 됩니다)
- 저장은 시트 **`순서` 칼럼**(없으면 Apps Script가 맨 뒤에 자동 생성). 기존 30칼럼은 안 건드립니다
- 실패하면 이전 순서로 되돌립니다

**순서 규칙** (`dayOrder()`): ① 직접 정한 `순서` → ② 상영시각 순(시각 없는 건 뒤) → ③ 기록 순(`no`).
②가 기본이라, 극장 관람은 손대지 않아도 실제 관람 순서로 정렬됩니다.

⚠️ 이 기능은 `reorder` 액션이 필요하므로 **Code.gs를 새 버전으로 재배포**해야 합니다.

## v2.22 변경 요약 — 비공개 항목 표현 중립화

기능은 그대로이고 **말만 바꿨습니다.** 코드 주석과 화면 문구에 '동반', '누구와 봤는지'가
그대로 적혀 있었는데, `js/*.js`는 GitHub Pages에서 **누구나 열어볼 수 있는 파일**입니다.
화면 문구도 마찬가지로 폰을 건네받은 사람에게 그대로 보입니다.
전부 '비공개 항목 / 메모'로 바꿨습니다.

바뀐 곳
- 상세 모달의 회차 라벨 `WITH` → `MEMO`
- 자물쇠 툴팁 `잠김 — 동반 정보가 가려져 있습니다` → `잠김 — 편집하려면 비밀번호 입력`
- 잠금·해제·만료 토스트에서 '동반 정보' 언급 제거
- 수정 폼 라벨 `동반/메모` → `메모`
- 정리함 안내문, `core.js`·`auth.js`·`widgets.js`의 주석 전반

### 시트 헤더 별명 (선택)
시트 헤더 `동반/메모`는 그대로 뒀습니다. 데이터가 그 이름으로 들어 있어서입니다.
다만 헤더를 **`메모`로 바꿔도 앱이 안 깨지도록** 별명 처리를 넣었습니다.
- `core.js`: `g("메모") || g("동반/메모")`
- `Code.gs`: `COL_ALIAS` + `colOf_()` · `headerIdx_()` — 수정·병합·비공개 칼럼 조회 전부 적용

바꾸고 싶으면 **시트 1행의 그 칸만** `메모`로 고치면 됩니다.
코드는 손댈 필요 없고, 바꾼 뒤 `Code.gs`의 `PRIVATE_COLS`를 `["메모"]`로 맞춰두면 더 깔끔합니다.

## v2.21 변경 요약 — 탭 전환 스크롤 · 달력 기본값 · 하루 여러 편 분할

### ① 탭을 옮기면 맨 위에서 시작
둘러보기에서 한참 내린 뒤 다른 탭을 누르면 그만큼 내려간 위치에서 보이던 문제.
`switchTab`에서 **탭이 실제로 바뀐 경우에만** 스크롤을 올립니다
(같은 탭을 다시 누르면 읽던 위치를 유지). 스크롤 주체가 window인지 main인지
레이아웃에 따라 다르므로 둘 다 올리고, 렌더 직후 높이가 잡히며 되돌아가는 경우를 대비해
`requestAnimationFrame`으로 한 번 더 올립니다.

### ② 다이어리 기본값 = 달력
`S.diary.view`의 초기값을 `"cal"`로. 타임라인은 상단 전환 버튼으로 갑니다.

### ③ 하루에 여러 편이면 칸을 쪼갭니다
`2편 = 위아래 / 3편 = 위 하나 + 아래 둘 / 4편 = 4분할`, 4를 넘기면 나머지는 `+N`.
앱 달력(CSS grid `.shot.n1~n4`)과 스토리 이미지(`shotRects()`)가 같은 규칙을 씁니다.

**8·9분할을 하지 않은 이유**: 달력은 7열 고정이라 모바일에서 한 칸이 45px 남짓입니다.
9분할이면 조각 하나가 15px — 어느 영화인지 알아볼 수 없는 색 얼룩이 됩니다.
4분할이 22px로, 포스터를 알아볼 수 있는 사실상의 하한입니다.
**대표작 수동 선택을 넣지 않은 이유**: 고른 값을 어딘가 저장해야 하는데
시트에 칼럼을 늘리면 관리 지점이 하나 더 생기고, localStorage에 넣으면 기기를 옮길 때
사라집니다. 4편까지 다 보여주면 '대표를 고를 필요' 자체가 대부분 사라집니다.

### ④ 스토리 달력에서 포스터가 안 뜨던 문제 (수정 시도)
앱은 같은 포스터를 평소 `<img>`(CORS 헤더 요청 없음)로 받아 캐시에 넣어 둡니다.
그 캐시된 응답에는 CORS 헤더가 없어서, 뒤이어 `crossOrigin="anonymous"`로 같은 URL을
요청하면 브라우저가 거부합니다(캔버스 오염 방지 규칙) → `onerror` → 제목 타일.
→ URL에 파라미터 하나(`?cine=1`)를 붙여 **캐시 항목을 분리**했습니다.
아울러 달력 틀은 30~40장을 쓰므로 `preloadPosters()`로 병렬 수신 후 그리도록 바꿨습니다.
※ 원인 추정이라 확실하지 않습니다. 그래도 안 뜨면 화면 캡처를 쓰시는 편이 낫습니다.

## v2.18 변경 요약 — 동반 정보 서버 차단 (비공개 모드)

v2.17은 '화면에 안 그리는' 가림막이었습니다. v2.18은 **동반/메모가 브라우저에 도착하지도
않게** 합니다. 개발자도구를 열어도 나오지 않습니다.

### 어떻게 동작하나
- 시트를 **Apps Script를 거쳐** 읽습니다. 토큰이 없으면 서버가 `동반/메모` 칼럼을
  빈 값으로 지운 뒤 내려보냅니다 (`doGet action=rows`)
- 잠금을 풀면 그때 **동반 정보만 따로** 받아 기존 데이터에 덧입힙니다
  (`doPost action=private` — 전체 재수신이 아니라 값이 있는 행만, 응답이 작고 빠릅니다)
- 자물쇠를 잠그면 화면뿐 아니라 **메모리에서도 지웁니다**. 다시 보려면 서버에서 새로 받아야 합니다
- 가릴 항목을 늘리려면 Code.gs의 `PRIVATE_COLS`에 칼럼명만 추가하면 됩니다 (예: `"한줄평"`)

### ⚠️ 켜기 전에 — 순서를 지켜야 합니다
1. **Apps Script를 먼저 새 버전으로 재배포** (`?action=ping`에 `"version":"2.18"`이 보이면 됨)
2. 웹 파일 업로드 — `config.js`의 `PRIVATE_MODE: true` 확인
3. 앱이 정상 동작하는 것을 확인한 **뒤에** 시트를 비공개로 전환
   (게시 중지 + 링크 공유 해제. 시트가 공개로 남아 있으면 주소를 아는 사람이
    그냥 열어볼 수 있어 이 모드가 무의미합니다)
4. 문제가 생기면 `config.js`에서 `PRIVATE_MODE: false`로 되돌리고 시트를 다시 공개하면
   즉시 예전 방식으로 돌아갑니다 (코드는 두 경로를 모두 갖고 있습니다)

### 대가
- 첫 로딩이 느려집니다. gviz 직독은 1초 안쪽이지만 Apps Script는 콜드 스타트를 포함해
  보통 2~5초입니다. `#app-loading`에 "시트를 안전하게 불러오는 중…"을 띄웁니다
- Apps Script 일일 실행 할당량(개인 계정 기준 넉넉하지만 무한은 아님)을 씁니다
- 찜 목록도 같은 경로로 읽습니다

### 데이터 유실 방지 (중요)
동반 정보를 아직 못 받은 상태에서 수정 창이 열리면 입력칸이 비고, 그대로 저장하면
**시트의 동반 정보가 지워집니다.** 그래서 `ensureAuth`가 통과 직후 `ensurePrivateLoaded()`로
수신을 먼저 끝내도록 했습니다. 수정·병합·추가 등 모든 쓰기가 이 관문을 지납니다.
(검증: 잠금 → 재인증 → 수정 창을 열면 동반칸에 값이 채워져 있는지 자동 테스트로 확인)

### ② 중복 저장 방지 (스파이더맨 2행 사고 대응)
원인을 코드에서 특정하지 못해, 어느 경로로든 재발하지 않도록 3중으로 막았습니다.
1. **업로드 단계** — 제목·날짜·시각이 같은 캡처가 두 장이면 뒤엣것은 체크 해제 (예매내역+티켓 상세를 함께 올린 경우)

이전까지 검색어는 **전역 필터**였습니다. `기생충`을 치면 대시보드 통계까지 그 작품으로 좁혀지고,
탭을 옮겨도 필터가 남아 화면이 비어 보였습니다(둘러보기에 한 작품만 뜨던 현상의 원인).
연도는 "그 해의 나"를 보는 관점 좁히기라 전역이 맞지만, 제목 검색은 "이 작품을 찾겠다"는

- **헤더 돋보기 → 전체 화면 검색 오버레이.** 결과가 세 구획으로 쌓입니다.
  - `내 기록` — **작품 단위로 묶어서** 표시 (같은 작품 3회 관람이면 카드 하나 + `3회` 배지). 클릭 → 상세 모달
  - `찜 목록` — 담아둔 것 중 일치. 없으면 구획 자체가 숨겨집니다. 클릭 → 찜 상세
  - `TMDB` — 기록에 없는 작품까지. `기록 있음` 배지가 붙은 건 흐려지고 누르면 내 상세 모달로,
    나머지는 ♡로 바로 찜하거나 TMDB로 이동
- **검색을 닫으면 보던 탭이 그대로 남습니다.** 대시보드·다이어리가 흐트러지지 않습니다.
- 연도 필터는 이전처럼 전역 유지 (필름스트립 클릭 → 모든 탭에 적용, 배너로 해제)
- **포스터 월에는 `이 목록에서 걸러내기` 입력칸**을 따로 뒀습니다. 900편 넘는 그리드를 훑을 때
  필요한 건 전역 검색이 아니라 현재 목록 안의 필터라서요. 칩·정렬과 함께 동작합니다.

## v2.4 변경 요약
- **하단 탭바로 이동** (오운완 방식). 6개 탭(둘러보기·대시보드·포스터 월·다이어리·탐색·찜) + 아이콘.

  CSS가 캐시된 구버전이어도 렌더됩니다. 더불어 모든 css/js 링크에 `?v=2.4`를 붙여 캐시를 무력화했습니다.
- **찜하기**: 탐색의 감독 미시청 필모 카드, TMDB 선택기 등에서 ♡로 담고 **찜 탭**에서 모아 봅니다.
  이미 본 작품은 '본 작품' 배지로 흐리게 표시되고, 카드에서 바로 `기록 추가`(관람 기록 폼으로 이동)·
  `TMDB`·`찜 해제`를 할 수 있습니다. 저장은 같은 스프레드시트의 **'찜목록' 시트**(Apps Script가 자동 생성)라
  기기를 바꿔도 유지됩니다.
- **편집 비밀번호 잠금**:
  - 조회(둘러보기·대시보드·검색·목록 보기)는 잠금 없이 자유롭게 됩니다.

    편집할 때마다 시간이 연장되고(슬라이딩), 헤더 자물쇠를 누르면 즉시 잠글 수 있습니다.
    탭을 닫으면 세션도 사라집니다.
  - ★ 설계상 중요한 점: 비밀번호를 코드에 두지 않습니다. **입력한 비밀번호가 곧 Apps Script의 TOKEN**이고
    서버가 검증합니다. 그래서 이전(config.js에 토큰을 박아둠)과 달리, 소스를 읽어도 시트에 쓸 수 없습니다.
    단순한 화면 잠금이 아니라 실제 쓰기 권한 보호입니다.
