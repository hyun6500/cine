# 주현 시네마테크 — 시청기록 아카이브 앱 v2 (모듈 구조)

15년 관람 기록을 구글 스프레드시트 DB로 보여주는 개인 아카이브.
오운완(hyun6500.github.io/JH)과 같은 GitHub Pages 정적 앱 + Apps Script 쓰기 패턴.

## 파일 구조
```
index.html            마크업 셸 + 스크립트 로드 순서 (core → poster → widgets → page-* → main)
css/style.css         테마 토큰 → 컴포넌트 → 반응형 순
js/core.js            [1순위] CONFIG·상수·전역 상태 S·시트 로딩/파싱·파생지표·탭 라우팅
js/poster.js          TMDB 조회 계층 (키 직접 또는 Apps Script 프록시, 타입 폴백, localStorage 캐시)
js/widgets.js         공용 위젯 (모달·토스트·카운트업·캐러셀 카드·평가 배지)
js/page-browse.js     둘러보기 (빌보드·TOP10·인생작 셀렉션·캐러셀)
js/page-dash.js       대시보드 (KPI·도넛·장르·감독·극장·월별·평가 분포)
js/page-wall.js       포스터 월 (칩 필터·정렬·무한 더보기)
js/page-diary.js      다이어리 (월별 타임라인)
js/page-explore.js    탐색 (장르·감독·연도·플랫폼·국가 + 감독별 미시청 필모)
js/page-add.js        기록 추가 (TMDB 검색 단일 입력 + 넷플릭스 CSV 일괄 업로드)
js/main.js            [마지막] init() 진입점 + 내장 샘플
apps-script/Code.gs   시트 쓰기(doPost) + TMDB 프록시(doGet)
```

## 신규 칼럼 4개 반영
| 칼럼 | 앱에서의 사용 |
|---|---|
| `관람상태` | '중도포기' 16행은 파싱 단계에서 제외 — 모든 화면·집계에 안 나옴 |
| `시즌` | 카드·모달에 `S1` 태그. 작품 동일성 키에 포함 → 같은 ID라도 시즌 다르면 별도 작품 |
| `TMDB타입` | 포스터·백드롭 조회 시 movie/tv 결정. **카테고리로 추론하지 않음.** 타입 미기재+ID 보유 시 movie→tv 순 폴백 |
| `넷플릭스평가` | 포스터 우하단 👍👍/👍/👎 배지 · 둘러보기 '인생작 셀렉션' 캐러셀 · 대시보드 평가 분포 차트 · 포스터 월 평가 칩 필터 |

작품 동일성 키: `TMDB_ID + 시즌` 우선, 없으면 정규화 제목. 같은 작품인데 일부 행에만
ID가 있는 경우(재관람 지연기록 등)는 로딩 시 제목→ID 백필로 보정한 뒤 키를 만듭니다.

## 설치

### 1. 설정은 js/config.js 한 곳에서만
개인 값은 전부 `js/config.js`에 있습니다. **앞으로 코드를 업데이트할 때 이 파일만 그대로 두면
키가 지워지지 않습니다.** (core.js는 마음 놓고 덮어쓰세요.)

```js
window.CINE_CONFIG = {
  SHEET_ID: "1xf26f…",         // 입력돼 있음
  TMDB_KEY: "…",               // 방법 A: 본인 v3 키 (클라이언트 노출)
  APPS_SCRIPT_URL: "",         // 방법 B: 프록시 + 기록 추가/수정 — 아래 2번 배포 후 URL
};
```
※ 편집 비밀번호는 config.js에 두지 않습니다. Apps Script의 `TOKEN`이 곧 비밀번호이고, 앱에서 직접 입력합니다.
⚠️ URL은 **끝까지** 붙여넣고 따옴표로 닫아야 합니다. 주소창에 `…`로 줄여 보이는 걸 복사하면
문자열이 안 닫혀 앱 전체가 멈춥니다(증상: 클릭 무반응 + "불 꺼지는 중…"에서 정지).
정상 URL은 `/exec`로 끝납니다 — Apps Script [배포 → 배포 관리]의 복사 아이콘을 쓰세요.

TMDB_KEY와 APPS_SCRIPT_URL 중 하나만 있으면 포스터가 뜹니다. 둘 다 있으면 키 직접 호출 우선.
단, **기록 추가·수정 기능은 APPS_SCRIPT_URL이 있어야** 동작합니다.

### 2. Apps Script 배포 (기록 추가 + 프록시)
1. 구글 시트 → 확장 프로그램 → Apps Script → `Code.gs` 내용 붙여넣기
2. `TOKEN` 값을 원하는 **편집 비밀번호**로 변경 (앱에서 이 값을 입력합니다)
3. (프록시 쓸 경우) 프로젝트 설정 → **스크립트 속성**에 `TMDB_KEY` 추가
4. 배포 → 새 배포 → 웹 앱 / 실행: **나** / 액세스: **모든 사용자** → URL 복사
5. ⚠️ 코드를 고치면 반드시 **"새 버전으로" 재배포** — 안 하면 옛 코드가 계속 돕니다
6. 동작 확인: `{URL}?action=ping` 접속 시 `{"ok":true,...}`

### 3. GitHub Pages 배포
```bash
# hyun6500.github.io 저장소에서
mkdir -p cine && cp -r index.html css js cine/
git add cine && git commit -m "cine v2: 모듈 구조 + 기록추가 + 탐색" && git push
# → https://hyun6500.github.io/cine/
```

## 기록 추가
- **한 편 추가**: TMDB 검색 → 선택하면 감독·장르·연도·ID·타입 자동. TV 선택 시 시즌 입력칸 등장.
  검색 없이 직접 입력만으로도 저장 가능.
- **넷플릭스 CSV**: Title/Date CSV를 올리면
  - 회차 단위 행을 **시리즈명+시즌으로 묶고** 시작~종료일 산출, **종료일이 대표 날짜**, 화수는 최대 회차번호
  - 기존 기록과 대조: 시리즈는 정규화제목+시즌 일치 시 '보유', 영화는 같은 날짜면 '중복',
    다른 날짜면 '재관람'(규칙대로 복수 카운팅 — 기본 체크됨)
  - 미리보기에서 제목·시즌 수정, 체크 선택 후 전송
  - '선택 행 TMDB 매칭' 버튼: 검색 결과가 **정규화 제목 완전 일치일 때만** ID·감독·장르 채움 (오매칭 방지)
- 저장 성공 시 화면에도 즉시 반영(낙관적 갱신). 시트 값이 진실이므로 새로고침하면 시트 기준으로 다시 로드.
- 앱이 시트에 쓰는 분류값은 **TMDB제작/감독·TMDB장르 칼럼**에만 들어갑니다 (KOBIS 칼럼은 건드리지 않음).

## 기록 수정 (v2.1)
상세 모달의 각 관람 회차에 **수정** 버튼이 있습니다.
- **작품 정보**: 제목·개봉연도·감독·장르·제작국가·TMDB_ID·타입. 'TMDB에서 찾기'로 고르면 한 번에 채워집니다.
  감독·장르는 KOBIS 칼럼에 기록되므로 화면에 바로 반영됩니다.
- **관람 정보**: 날짜·시작일·시즌·카테고리·플랫폼·위치·상영시각·화수·동반메모·평점·넷플릭스평가·한줄평
- 같은 작품을 여러 번 봤다면 **'N회차 전체에 작품 정보 함께 적용'** 체크로 한 번에 정리됩니다
  (관람 정보는 언제나 그 회차에만 적용).
- 저장은 Apps Script `update` 액션 → `no`로 행을 찾아 해당 칼럼만 덮어씁니다. 화이트리스트 밖 필드는 무시됩니다.

## 탐색

- 감독 선택 시: 내 관람작 + **아직 안 본 작품** (TMDB person combined_credits에서 Director 크레딧 추출
  → 내 기록의 TMDB_ID·정규화 제목과 대조해 미시청분만, 최신순). 클릭하면 TMDB 페이지로.
- 대시보드의 감독 랭킹을 클릭해도 이 상세로 들어옵니다.

## 아키텍처 결정 (질문 답)
1. **메타데이터는 시트 저장분 사용** — 맞습니다. 감독·장르·연도·등급은 매 방문 API 호출 없이 시트 값만 씀.
2. **포스터**: TMDB 실시간 조회 + localStorage 캐시(`pc2`) 유지. poster_path를 시트에 넣는 방법도 가능하지만
   칼럼 1개·991행 채우기 관리 비용 대비, 캐시가 이미 재방문을 0콜로 만들어 이득이 작음.
   TMDB_ID 329건은 정확 조회되고, ID 없는 작품만 멀티 검색 폴백.
3. **키 노출**: GitHub Pages 정적 사이트에선 클라이언트에 넣는 값은 어떤 방식이든 결국 공개됩니다
   (`.gitignore`로 빼면 배포에 포함되지 않아 동작 자체가 안 함).
   - TMDB v3 키는 읽기 전용·무료라 실위험은 '남이 내 쿼터를 씀' 수준 → 노출 감수 가능
   - 정말 감추려면 **Apps Script 프록시**(방법 B): 키는 스크립트 속성에만 있고 클라이언트엔 프록시 URL만 노출
   - 쓰기 토큰(APP_TOKEN)도 노출되지만, 최악의 경우 스팸 행 추가 정도이고 시트 버전 기록으로 복구 가능.
     신경 쓰이면 주기적으로 토큰만 교체(Code.gs와 CONFIG 동시 변경)

  - 찜 상세에도 같은 `봤어요` 버튼을 달았습니다
- **둘러보기에 `내 별점 TOP`** 캐러셀 추가. 위치는 **인생작 셀렉션 바로 위**이고 카드마다 `★ 4.5` 배지가 붙습니다.
- **탐색 탭의 🧹 버튼을 `정리함`으로 확장**했습니다(손볼 건수가 있으면 칩에 빨간 배지).
  네 갈래로 나눠 봅니다: `중복 후보`(기존 중복 점검) · `제목 미상` · `정보 없음`(TMDB 미연결·감독/장르 공란) ·
  `날짜 미상`. 각 행의 `수정` 버튼으로 바로 편집 창이 열립니다.
